# AG Relay 0.3.12

## 长时间请求不再被退出超时打断

- 安全退出与更新不再固定只等 10 秒。等待期间可以查看进度，也可以取消等待并恢复接单。
- 正在生成长回复或执行长任务时，退出会等待请求自然结束，而不是先取消退出、让你稍后再试。
- 只有确实需要你决定时才会中断；取消等待后网关照常接单，不会偷偷排队退出、重启或强制结束请求。
- 安全边界不变：不强制中断在途请求，也不会在后台自动退出。

## 报错编号不再干扰错误恢复

- 修复了一类误判：上游报错附带的请求编号里恰好含有 `502`、`503` 等数字时，网关会误以为是服务器临时故障，跳过本可自动完成的加密历史修复，把原始 400 直接显示在对话里。
- 现在请求编号、trace 编号、条目编号、链接和无关字段都不再参与错误判断；真正的限流、余额不足、鉴权失败和上下文超限仍会及时显示，不会被重试掩盖。
- 普通 HTTP 报错、流式回复中的报错和“状态 200 但正文是错误”三种情况使用同一套判断，不再出现同一种错误在不同通道下处理结果不一致。
- 加密推理历史失效、跨资源引用、状态字段被拒绝等明确错误仍按原有安全规则处理；能安全修复时会内部修复一次，不能安全修复时保留历史有限重试，不删除工具调用与消息内容。

## 使用提醒

- 本次改善的是“本可自动恢复却被误判打断”的情况，不保证所有上游报错都能恢复。上游通道本身拒绝解密或拒绝请求时，仍可能需要你手动继续。
- 历史修复是有损兼容：修复会移除失效的旧推理记录，可能损失推理连续性，不等同于恢复完整历史。
- 安装前请有序退出旧版应用与网关；安装器不会替你强制结束正在工作的实例。
