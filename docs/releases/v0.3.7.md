# AG Relay v0.3.7

## Codex 历史恢复更保守

- 仅针对明确识别出的 Codex Responses 请求。正常请求原样发送；连续两次同类历史资源错误后，才尝试一次安全剥离。
- 剥离后的同一份请求最多再发送三次；历史错误累计最多五次，并继续受原时间预算和取消控制约束。不会越失败越多删内容。
- 每条新请求重新带原始历史发送，不再因这段 Codex 对话之前修复过，就提前清理后续请求。
- 失效推理错误只处理旧推理历史；跨资源错误另外处理允许省略的条目编号。消息正文、工具参数、工具结果和调用配对保留。
- 补齐完整网页搜索历史的处理，保留其必需编号、动作和状态。不能安全处理的服务器引用、压缩历史或不完整工具记录仍保留原文，不强行删除。

## 不影响正常链路

- Claude、ZCode 和其他未进入新模式的请求维持原有处理；客户端标记不明确或互相冲突时，不启用新的 Codex 降级规则。
- 不调整通用重试次数、间隔、超时、鉴权或额度不足处理；已经交付内容后不重放，客户端取消后不继续请求。
- 不为普通限流或空响应启用新的 Codex 历史剥离。上游兼容问题修复后，未命中指定错误的请求自然不再降级。

## 使用与安装

- 历史剥离是有代价的兜底：保留消息和工具记录不等于保留全部推理连续性，也不保证所有上游历史问题都能恢复。
- Windows x64：一般用户选择 `ag-relay_0.3.7_x64-setup.exe`；需要 MSI 的用户选择 `.msi`。
- 隔离网关回归 29 项通过，1 项既有手动性能观察默认忽略；诊断契约 17 项、默认配置 2 项、发布工具 35 项通过。前端构建及含安装器运行时的 724 个组件许可校验通过。
- 本次发布不自动安装或重启现用网关，未在维护者正在使用的环境运行安装器。请等当前请求结束后手动更新。
