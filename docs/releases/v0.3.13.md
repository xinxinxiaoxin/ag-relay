# AG Relay 0.3.13

## 修复版请求不再被三次上限提前掐断

- 之前有一类失败占了你 Codex 报错的绝大多数：网关明明按你设置的次数（默认 110 次 / 5 分钟）在重试，实际却只试 3 次就放弃，然后把错误交给 Codex。
- 原因是会话一旦被登记过历史兼容处理，之后这个会话的每个请求都被当成“修复版”，一律受“最多再发 3 次”的限制——哪怕这次的失败只是上游限流，跟历史毫无关系。
- 现在这条 3 次上限只约束**真的报过历史错误、并且确实做了有损降级**的请求。只做会话预清理、没有历史错误的请求，按你配置的次数和总预算重试。

实测依据：一天内 83 个 Codex 请求因这条上限失败，其中真正的历史错误为 0，全部是限流；同一时段 Claude 的 69 个限流请求有 67 个在 3 次左右的重试后成功。修复后这两类请求的重试深度一致。

## 中文“无可用渠道”不再白白重试两百秒

- 中转站用中文返回“无可用渠道 / 无可用模型”时，以前不被识别为通道问题，会落进通用重试，一路试满 110 次、约 200 秒才放弃。
- 这类请求主要来自 Codex 自己的后台辅助调用（压缩对话、生成摘要）。它们失败时不会弹窗，你只会觉得变慢；但每个请求会一直占着上游连接和限流配额，拖累主对话。
- 现在识别为通道抖动：放开到 8 次、约 6 秒内收手，并返回可重试状态。**这不等于让这些辅助请求成功**——它们的模型名在当前站点没有通道，仍会失败，只是不再长时间占用连接。

## 使用提醒

- 本次不改变你配置的重试次数、退避间隔和总预算，也没有放宽历史改写、工具配对和取消边界。
- 真正的历史降级行为不变：一次修复、修复后冻结请求体、最多再发三次、历史错误累计五次。
- 安装前请有序退出旧版应用与网关；安装器不会替你强制结束正在工作的实例。
