发现（**均为需要维护者决策、不应擅改历史或覆盖已发布资产**）：

1. **隐私残留**：两版 `ag-relay.exe` 各含约 325 处构建账户路径字符串（`.cargo` 构建目录等）。这不是凭据泄露，但公开后属于可被读取的本机信息。本规格的新构建已加入 Rust 路径重映射与产物检查（见 §5），但**旧资产无法追溯清理**。
2. **许可材料缺项**：两个旧 ZIP 都没有随附 `LICENSE` / `THIRD_PARTY_NOTICES` / 许可目录。新版本已补齐并在安装包内携带（见 §5）。
3. `node.exe` 与仓库内的 sidecar 摘要一致（`ac51903c…c8582`），匹配 nodejs.org 官方 SHASUMS 记录的 v24.18.1；其中的令牌形状命中均属该官方二进制自身内容。
4. 两版主程序**没有嵌入式 Authenticode 证书表**。这与 updater 的签名校验是两件事：旧 ZIP 并未接入 updater，不能把「无 PE 签名」说成「更新验签失败」。

对 spec #19 阶段的 NSIS/MSI 候选做了静态检查：用 `dark` 提取 MSI 的 418 个文件、用标准库 LZMA 解开 NSIS 固实流（110 065 996 字节 / 419 块，未解析余量 0），未调用任何安装接口。

- 两种包都包含 404 份许可材料，与当时比对的工作树逐字节一致。
- 载荷中未检出私钥材料；外层四处 “secret key” 启发式命中已确认是公开的 minisign 签名注释，不是私钥。
- 两份 `.sig` 与 `latest.json` 用测试公钥离线验签通过；翻转字节后均被拒绝。
- 两版主程序各含约 660 处本机构建路径（**因为该候选尚未启用路径重映射**，属预期）。
- 该候选用于验证「能构建、能验签」，**不是最终功能成品，也不代表安装可用**。

- 构建期对 Rust 编译路径做重映射，并在出包前静态检查产物是否仍含本机构建前缀；有残留则不出可发布目录。
