# 重试与取消边界（2026-10-14）

## 范围与优先级

本次基于用户明确授权实现交接清单第 1 项。速度优先，不调重试次数、间隔、抖动、超时或长流预算；不增加用量/tok/s 统计、正文落盘或上游请求。单一上游、客户端密钥边界保持不变。

## 已复现的问题

既有 `gateway_connection` 集成接缝：自造临时目录、随包 Node、随机本机端口、假上游、假凭据。测试没有访问现用实例。

1. 503 后等待重试时取消：假上游收到 **2 次而非 1 次**。仅修每轮入口后，虽然不再多发请求，100ms 后 `activeRequests` 仍为 1，暴露不可取消的等待。
2. 同一个上下文超限错误：HTTP 400 只尝试一次，HTTP 200 的 SSE 错误触发了第二次请求。
3. 只有错误码、没有报错文案的 `invalid_api_key` 流式错误仍被重试。

## 修复与兼容边界

- 取消监听在接收请求体之前安装；响应已断开时立即返回。每轮尝试都检查取消，不再只检查 Codex 资源重试分支。
- 退避等待监听同一取消信号，取消即清计时器并结束；等待结束移除其监听。
- 每次尝试的父级取消监听保留到响应读取完成，在 `finally` 移除。响应头超时计时器在响应头后清除，仍不按总预算截断正常长流。
- 普通 HTTP、200 JSON 错误体、下发前 SSE 错误共用既有确定性错误规则，兼容仅有错误码的情况。仅在明确错误信封上读取 code/message；未扩大正文采集范围。
- 精确匹配的状态/历史兼容修复仍先执行；部署缺失保留快速换通道重试。未知 SSE 错误仍沿用原来的重试处理，不以“不认识”认定永久错误；泛化的 `invalid_request_error` 类型本身不作为新增的停重试证据，仍按具体原因判断，避免误拦包装在此类型下的限流。
- 已下发内容后不重放整个请求；成功流字节与终止标记保持原样。
- 请求取消后的异常不再尝试向已销毁的响应写错误。

字典去掉“下发前失败必然换通道重试”的旧说明。合成诊断样本 `src-tauri/tests/fixtures/diagnostics-retry-boundaries.jsonl` 保留同一事件形状，集成回归验证确定性失败的 `retryable=false` 及不落盘错误正文。历史真实样本不改写。

## 2026-10-17：仅 Codex 的明确错误后会话降级（当前方案）

用户在真实通道对照后确认：只改 Codex；正常首发不做全量推理剥离，首次明确历史错误后尝试有损兼容，同会话后续首发预处理；Claude 保持原行为。此方案取代下一节的“含搜索就一直拒绝降级”保护，不把群里的三条删除规则无条件套到所有请求。

- 严格 Codex 识别、`POST /v1/responses` 和既有兼容开关限定新路径；跨 Azure 资源、失效推理、缺配套推理等明确历史错误才能触发。仅 Codex 的错误入口加强确定性错误优先级，限流、网络、空响应、鉴权、额度和上下文超限不被历史文案误导。
- 正常首发仍保留搜索及配套推理编号；已确认历史错误后的完整内联降级，同时去掉旧 reasoning 和支持项的顶层 id（含 web_search_call），保留搜索 action/status/type、来源扩展、消息、工具输入输出及 call_id。不是删除整个搜索，也不把搜索转成正文；它仍会损失旧推理与资源关联。
- 完整搜索支持 query/queries、open_page、find_in_page 的既有形状。已省略 id 的完整搜索也可通过降级校验。未知动作、未知条目、不完整工具配对及非 reasoning 密文仍拒绝改写。
- 非空 previous_response_id、conversation、item_reference、压缩历史不能被盲删；无法证明完整内联历史时拒绝新增降级，保留现有请求走有限重试。实际失败的用户请求没有 previous_response_id，这条保护不阻碍其恢复路径。

上游服务正在修复 Responses 历史兼容问题，本次将网关兜底限制为当次请求，不让历史恢复演变为持续清理模式。仅明确识别为 Codex 的 `POST /v1/responses` 启用新策略；其他客户端保持原有处理，不根据模型名称猜测来源。

- 相邻两次同类跨资源或失效推理错误才进入一次安全修复；不同历史类别、限流、断网及空响应不能凑满门槛。
- 在第二次错误之后、第三次发送之前修复内存副本，不额外增加一次所谓“修复请求”。连续同类失败的典型序列为原样、原样、修复版、修复版、修复版。
- 失效推理错误只去掉旧 `reasoning`；跨资源错误另处理可省略的条目编号。完整网页搜索历史的必需 `id/action/status/type` 保留；正文、工具参数、结果和 `call_id` 配对不变。
- 应用修复后冻结请求体，最多三次实际发送，包括其间发生的通用可重试错误；历史错误累计最多五次，并沿用原总预算、重试准入和取消控制。
- 每条新 Codex 请求重新原样发送，不查询或登记旧会话兼容预清理记忆；旧空回形状降级不能绕过新模式的明确错误门槛。其他客户端既有兼容缓存不变。
- 无法安全改写的服务器引用、压缩密文、未知历史或不完整工具记录保留原始字节，在剩余限制内重试；已经交付内容后不重放。
